# knowledge retrieval 内存规则

只在知识库非空、Codex 已从输入识别出主题后调用 `knowledge_run.py context`。它在内存中扫描当前 Markdown 并返回有限相关原文，不生成 inventory 或 retrieval 文件，也不依赖 Candidate ID。

返回值使用 `conversation-knowledge-curator.context.v1`，主要字段如下：

```json
{
  "path": "preferences/development-tools.md",
  "heading_path": ["开发工具偏好", "默认 IDE"],
  "score": 18,
  "matched_terms": ["ide", "开发"],
  "markdown": "## 默认 IDE\n..."
}
```

- `score` 只用于当前查询内部排序，不是相似度概率或知识价值评分。
- `matched_terms` 说明哪些规范化关键词参与得分，不代表语义等价。
- `markdown` 是为本次融合判断返回的有限原文，不保存到 run。
- 排序先按 `score` 降序，再按路径和章节顺序稳定决定。

## 关键词与计分规则

第一版不依赖分词库、Embedding 或数据库：

- 英文、数字和常见技术标识按完整词提取并转为小写；支持 `C++`、`C#`、`.NET` 和 `B+Tree` 这类常见写法。
- 连续中文文本只生成相邻双字词；单个汉字和完整长句不进入输出，避免通过 `matched_terms` 复制候选原文。
- 查询和路径、标题、标题路径、正文采用同一套词项提取规则，并按完整词匹配。`SQL` 不会命中 `NoSQL`，`Go` 不会命中 `MongoDB`，`index` 不会命中 `indexing`。
- 同一关键词在路径、文档标题、标题路径和章节正文中分别只计分一次。
- 路径命中权重为 `8`，文档标题为 `6`，标题路径为 `5`，章节正文为 `1`。
- 任一查询词命中即可召回，得分为 `0` 的章节不输出；当前不设置最低分阈值。
- 算法只做字面词项匹配，不进行同义词、缩写或其他语义扩展。Codex 必须在后续阶段阅读必要原文并判断相关性。

## 召回策略与评估边界

当前版本优先为后续语义判断提供较宽的候选范围，但在建立标注样本前，不宣称算法已经达到“高召回率”。权重和默认数量只是初始规则，不应根据少量个案频繁调整。

后续应使用真实脱敏样本建立评估集，至少记录：

- `Recall@5`、`Recall@10` 和 `Recall@20`，检查应召回章节是否进入前 N 名；
- `Precision@5`，观察靠前结果中有多少确实相关；
- 漏召回原因和误召回原因，用于决定是否需要中文停用词、IDF、短语邻近或其他改进。

## 输入与安全校验

`context` 必须先确认知识库快照仍与 `run.json` 一致，拒绝路径越界和链接。空知识库返回 `skipped_empty_knowledge_base`，不执行检索。`--limit` 允许 1 到 20；结果只帮助 Codex决定读取范围，不能自动决定融合或写入。
